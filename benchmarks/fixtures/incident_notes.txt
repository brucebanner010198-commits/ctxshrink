In order to understand why the checkout flow is failing, it is important to note that
due to the fact that the discount cache is not being invalidated on write, stale
discount codes are able to be applied even after they have expired. Please note that
this is able to cause a number of downstream failures in the tax calculation step,
because the subtotal is computed prior to the discount being resolved.

At this point in time, the recommended fix is to invalidate the cache in the same
transaction as the discount write. It should be noted that this is able to be done
without a schema change. For the purpose of avoiding a regression, we should also add
a test that exercises the case where a discount expires while an order is in flight.

Basically, the majority of the reported incidents trace back to this single root
cause. Generally speaking, once the cache invalidation lands, we expect the error
rate to return to baseline within a single deploy cycle.
